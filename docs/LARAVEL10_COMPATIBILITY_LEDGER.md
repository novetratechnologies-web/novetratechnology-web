# Laravel 10 integration and compatibility ledger

Snapshot: 2026-10-15. Findings are based on source inspection and the baseline smoke checks. High-risk untested areas must be covered before beginning a framework-major migration.

| Integration surface | Location | Current design / finding | Risk and next action |
|---|---|---|---|
| Provider registration | `config/app.php` | Laravel framework providers, package auto-discovery and app providers; custom `RouteServiceProvider`, `AuthServiceProvider`, `AppServiceProvider`, broadcast provider | Laravel 11 changes bootstrap/provider registration conventions; preserve explicit provider behavior during upgrade |
| Routing | `app/Providers/RouteServiceProvider.php`, `routes/web.php`, `routes/api.php`, `routes/admin.php`, `routes/guestapi.php` | Legacy controller namespace routing, separate admin prefix with `web`, `auth`, `churchadmin`; 730 registered routes | Large surface; route registration passes; capture route list and test critical named routes before/after framework upgrades |
| Middleware | `app/Http/Kernel.php`, `app/Http/Middleware/*` | Custom global middleware; API group includes stateful Sanctum, throttle, bindings; old `$routeMiddleware` aliases | Laravel 11 uses new bootstrap middleware API for new applications; retain behavior and test API/web/admin stacks explicitly |
| Authentication / roles | `config/auth.php`, `app/Providers/AuthServiceProvider.php`, `app/Policies/*`, Laratrust | Laravel session auth, Sanctum tokens, role IDs and church-specific Gate checks | Multiple auth concepts and manually defined policies; add multi-church isolation, role matrix, token lifecycle tests |
| Impersonation | `app/Http/Kernel.php`, `nckg/laravel-impersonate` | Impersonation middleware is in global HTTP stack | Sensitive global behavior; verify authorization, audit log, restoration, and API exclusion |
| Exception handling | `app/Exceptions/Handler.php` | Extends Laravel handler with pass-through report/render overrides | Remove dead overrides only after confirming custom reporting expectations; test JSON and web errors |
| Service provider / observers | `app/Providers/AppServiceProvider.php`, `app/Observers/*` | Registers many Eloquent observers, custom validation rule, dynamic church configuration, per-church custom mailer binding | Settings loading now guards for required tables and a configured church; custom mail binding was migrated from unavailable SwiftMailer classes to Symfony SMTP; audit the missing MailTracker package hooks and test queued delivery |
| Data model / migrations | `database/migrations/*`, `app/Models/*`, `app/Observers/*` | 94 project migrations, soft-deleted users, church ownership repeated across models, demo seeding | Multi-tenant integrity is a product-critical concern; add two-church tests for reads, writes, jobs, exports, notifications, storage, and API |
| Factories | `database/factories/*`, `laravel/legacy-factories` | Composer still loads legacy factory package; PSR-4 warning for `EventGalleryFactory` vs `EventgalleryFactory.php` filename | Rename/fix after checking filesystem and references; migrate remaining legacy factories before removing dependency |
| Queue / mail / SMS | `config/queue.php`, `config/mail.php`, `app/Traits/SmsProcess.php`, mail queue observers | Local default queue is sync; per-church SMTP transport now uses Symfony Mailer; three mailables use `withSymfonyMessage()` for their custom headers | Tests must use fake mail/queue/provider adapters and prove opt-out/consent checks. MailTracker package is absent although event and listener references remain; message-open/click tracking is not verified |
| Push notifications | `app/Services/FcmHttpV1Client.php`, `app/Notifications/Channels/FcmHttpV1Channel.php`, `app/Notifications/SendDeviceNotification.php` | Google service-account OAuth and FCM HTTP v1; payload unit test is offline | Verify token refresh, retry classification, invalid-token cleanup, per-user opt-in and channel policy with fakes |
| Giving / payment | `app/Http/Controllers/DonationController.php`, `app/Http/Controllers/Member/DonationController.php`, `app/Services/Payment/*`, donation-reference migration | Paystack, Flutterwave, and Stripe verification validates provider status, amount, and currency; unique church/gateway/reference index and recorder make duplicate verification idempotent | Signed callbacks, M-Pesa callback authenticity, reconciliation, and provider sandbox tests remain |
| Spreadsheet / CSV | `app/Imports/*`, `app/Exports/*`, import controllers | Laravel Excel 3.1 and PhpSpreadsheet 1.x; member import repair has a focused synthetic row test | PHP 8.5 and Excel 4.x are deferred; include malformed headers, duplicate identifiers, large files, and church boundaries in future tests |
| Storage / media | `config/filesystems.php`, medialibrary models, S3 adapter | Local and S3 adapters; Media Library 11.23.9 / Spatie Image 3.9.7; inspected usages are media traits and page attachment upload | Patched advisory range; integration-test conversions, authorization, cleanup and untrusted uploads |
| API resources | `app/Http/Resources/*`, Sanctum routes | Resource serialization used by API/mobile | API contract snapshots and cross-church authorization are missing; version/document contracts before building mobile clients |
| Install/bootstrap | `app/Console/*`, installer routes/controllers, migration/seeders | Install command validates payload, avoids secret logging, refuses initialized reruns, and wraps church/admin/profile creation in a transaction | Rerun is tested against synthetic schema; fresh first-run filesystem flow still needs a separate disposable app/schema |
| Configuration / deployment | `config/*`, `.env.example`, root files | Local DB, filesystem cache/session, synchronous queue by current local env; no tracked CI or container/deployment definition found | Publish a PHP 8.4 + database + Node support matrix and CI workflow before item 3; keep real secrets out of repository |
| Frontend compiler | `package.json`, `webpack.mix.js`, `resources/assets/*` | Laravel Mix 4 / webpack 4, Vue 2, Tailwind 1; builds with Node 24 via legacy OpenSSL option | Build passes but emits outdated Browserslist and Tailwind purge warnings; treat Vue/Mix/Tailwind modernization as separate frontend work, not part of PHP framework upgrade |

## High-priority follow-up list

1. Resolve the Laravel framework advisories and abandoned Doctrine annotations recorded in `COMPOSER_DEPENDENCY_INVENTORY.md` before production deployment.
2. Verify queued SMTP delivery and decide whether to restore/replace the absent MailTracker behavior.
3. Extend two-church coverage across writes, jobs, API, storage, and notification recipients (exports and admin donation lists are covered).
4. Add signed callback/sandbox tests for payment reconciliation and finish email/SMS/push consent coverage.
5. Exercise installer first-run and rerun safety in a separate disposable app/schema (rerun refusal is covered).
6. Add a CI pipeline that installs from lockfiles on PHP 8.4, checks Composer/platform, runs Artisan tests/routes and the frontend build.
7. Continue the PHP 8.4 deprecation/error pass. Global notice/warning suppression was removed; the current smoke suite passes with framework error handling active, but does not cover all registered routes.
